# Point-plane native profile: bounded acceptance

The AoSoA point-plane configuration at **exactly 1,025 correspondences** has three
controlled passing processes on Radeon 8060S and canonical RTX 4070 Ti. The reusable
core is `kernels/optimization/point_plane_inlined.slang`; the measured adapter is
generated by `benchmarks/inlined_point_support.py`. This is candidate evidence for
a separately compiled native Vulkan caller, with every incumbent retained.

No family-wide, all-size, Python, default, installed API or consumer migration
claim follows. Earlier 1,000-block Radeon suites failed the uncertainty gate;
the subsequent fixed 10,000-block precision experiment is shown separately.
A failed historical result is not relabeled as passing.

## Preserved operation and measured caller

The residual and rotation-first Jacobian retain the frozen generated arithmetic,
FMA schedule, indexed gathers, sequential target/normal rows, complete padded4+2
AoSoA output, bounds guard and poison padding. The reusable functions own no
resources or synchronization. The adapter preserves generated load/store phases.

Under both pinned compilers, the original 1024-thread native profile has an equal
normalized instruction stream and equal resource layout. The 256-thread profile
differs only in declared LocalSize; arithmetic, ordering, types, constants,
operands and decorations remain compared. The comparator checks actual LocalSize
before allowing that difference. Both profiles have exact numerical tests at
1,63,1023,1024,1025,4099,65539 on both physical GPUs.

The native caller uses Slang 2026.19 SPIR-V, shared retained buffers/descriptors,
cached host staging, a fresh submission/completion per invocation, and pinned
CPU 31 (Radeon) or 19 (NVIDIA). Baseline remains the frozen 1024-thread incumbent;
candidate uses 256. Both use the same explicit polling completion mode. Polling
consumes CPU while awaiting completion; every invocation retains thread CPU time.
This is not a claim of a cheaper blocking caller.

Three boundaries remain independent: dispatch timestamps; complete resident
record/submit/completion wall time; complete transfer wall time including all
uploads, output initialization, barriers, dispatch, both full downloads,
flush/invalidate and CPU copies. Query retrieval occurs outside its wall timer.
Allocations, compilation, descriptor creation and correctness dumps are outside
timing for both variants. Every individual ABBA invocation is retained.

## Exact bounded result

Radeon controlled AoSoA / 1025 median GPU ratio is 0.8571 in all three runs; resident
wall ratios are 0.9935/0.9931/0.9926 and transfer ratios are 1.0003/1.0000/0.9987.
Every median/tail bound passes. The shader is about 14% faster while full transfer
is on par under this caller profile. Median candidate thread CPU time is about
16 microseconds per resident completion and 32 microseconds per full transfer call.

Earlier matching NVIDIA iteration5 also passes all three runs: GPU ratios
0.5923/0.5962/0.5923, resident 0.8219/0.8217/0.8214 and full transfer
0.9178/0.9226/0.9185. These are seeded 1025-element results, not application FPS or
a size-range claim.

The matching 10,000-block NVIDIA experiment6 passes all three runs at every
boundary. GPU median ratios are 0.6320/0.6190/0.6154, resident wall ratios are
0.8531/0.8503/0.8496, and complete transfer ratios are 0.9241/0.9236/0.9246.
The complete per-run bounds and historical decisions are also collected in the
[machine-readable summary](evidence/native-acceptance-summary.json).

## Numerical and provenance checks

Final test runs: 96 passed on each GPU. Native build and 73 CPU-only CLI/fixture/
SPIR-V checks pass; CPU checks alone do not establish Vulkan correctness. Every
completed native process passed full-byte differential, independent poison
padding and independent float64 oracle checks before and after sampling.
Real module-import checks pass under both pinned compilers.

Each suite plan records source, compiled shader, native binary, fixture and output
hashes. Source hashes were checked against each recorded Git revision, including
the remote archive's explicit revision. Raw samples retain hardware/driver/API/
memory/affinity identities and CPU time. The lossless archive preserves every
original output and fixture path; see README for exact restoration. Python
reports remain separate evidence.
