# Experimental point-plane AoSoA dispatch

`optimization/point_plane_aosoa_256.slang` imports the existing shared point-plane math and preserves the candidate's 256-thread AoSoA adapter. It is an experimental source artifact, not a catalog operation or selected default. The caller owns every buffer, descriptor, dispatch, barrier, submission and lifetime. The provided `sintergpu.point_plane_aosoa_1025.fixture_plan` accepts only the frozen 1,025-element fixture and validates caller-attested allocation ranges, output non-overlap and explicit device limits before returning dispatch and parameter values.

Bindings 0–6 are points, targets, normals, residual output, Jacobian output, point indices and `CasparParams`. Inputs are float32 float4-stride points/targets/normals and uint32 indices. Output stores residual at `out_0[i]`, rotation-first Jacobian columns 0–3 at `out_1[4*i:4*i+4]`, and columns 4–5 at `out_1[4*out_1_num_alloc+2*i:...+2]`. The six uint32 parameters are `problem_size`, `points_num_alloc`, `targets_num_alloc`, `normals_num_alloc`, `out_0_num_alloc`, `out_1_num_alloc`. Dispatch 256 threads per group with rounded-up groups and preserve poisoned padding; the shader checks `i < problem_size`, not allocation or index validity.

The retained 1,025-element fixture and exact candidate shader are frozen from PR #14 at `2def63bb85adfcb0cb5b1b8d0910bed31dda0539`. The separately recorded candidate benchmark used a generated inline shader, native Vulkan caller, cached staging, matched polling and Slang 2026.19. Importing the packaged module changes compilation: these CPU and reflection checks do not establish GPU numerical parity or performance of this adapter. Source-bound GPU parity and controlled kernel, resident and transfer comparisons on each intended configuration remain pending. No wider size range, Python route, tracking or default-selection claim is made.

## Checked fixture-only host contract

Use `fixture_plan(limits=..., ranges=..., allocations_verified=True, fixture_contents_verified=True)` only after the caller independently verifies the actual device limits, buffer allocation identities and ranges, all fixture input uploads including indices, and initialized output padding. Ranges are whole bound byte ranges described by nonempty `allocation_id`, four-byte aligned `offset` and `length`; lengths must cover the frozen arrays and fit the supplied device buffer limit. Writable ranges must not overlap any other binding; read-only ranges may share. Allocation identifiers and boolean flags are caller attestations, not proof of physical backing or device contents. The plan returns exactly five 256-thread groups and the fixed six parameters plus two zero padding words. These fixed indices and extents avoid uint32 indexing overflow. Barriers, descriptor alignment requirements beyond four bytes, queue ownership and lifetime remain the caller's responsibility. Any other size or input is outside this checked fixture contract.
